Claude 使用指南

日常以 Claude Code CLI 为主，从网络配置到完成任务。

01 开始前，先把环境配好

使用顺序：网络与出口 → CLI 代理 → 安装登录 → 日常任务 → 命令与用量 → 维护排障。Windows 使用 PowerShell；macOS / Linux 使用系统终端。

推荐方案：各自已有的科学上网线路 + 静态家宽 IP，在 Clash Verge 中配置链式代理。 Claude / Anthropic 请求经前置节点连接家宽，最终由家宽访问服务；其他网站继续按原订阅规则访问。此方案无需自行购买 VPS 搭建中转。

截图上的几种地址怎么理解

「中转代理详情」中的主机、端口、用户名和密码是一套供应商接入信息；「出口 IP」是最终家宽出口，用来验收。Codex 会分开使用，不把出口 IP 当作接入端点，也不混用「原始代理」与「中转代理」的端口或认证。

02 推荐网络：Clash 链式代理

推荐链路：Claude Code / 登录浏览器 → 本机 Clash → 自己常用的梯子前置节点 → 静态家宽 IP → Claude / Anthropic。家宽负责最终出口，已有梯子负责连接家宽端点。

在 Clash Verge 中从哪里配置

  1. 打开左侧 订阅，选中平时使用且已经可用的通用梯子订阅。
  2. 找到页面中的 全局扩展脚本（Script），打开编辑。已有脚本时，让 Agent 把新增内容合并到原来的 main(config) 中，并保存原件。
  3. 加入静态家宽节点，在该节点上设置 dialer-proxy，指向现有梯子的一个稳定前置节点。再把 Claude / Anthropic 域名规则放到原规则前面，指向家宽节点。
  4. 先由 Agent 检查候选配置，再按已授权范围应用。运行时使用 规则模式；“全局扩展脚本”表示脚本的作用范围，与代理的“全局模式”不同。

全局脚本会处理各个订阅。切换订阅后，前置节点名仍须存在；不同订阅需要不同配置时，由 Agent 使用 profileName 区分。订阅更新后查看最终生成配置，确认链路和分流仍有效。

几个名称分别指什么

名称 在这套方案中的作用
前置节点 各自通用梯子中的节点，用来连接家宽代理端点
静态家宽节点 保存供应商地址、端口与认证信息，是 Claude 的最终出口
dialer-proxy 写在家宽节点上，值为前置节点或代理组的准确名称
HTTP / mixed 端口 CLI 连接本机 Clash 的入口；家宽即使是 SOCKS5，CLI 仍连接这里

家宽连接上限与校园网注意事项

部分产品限 2 台设备同时连接，具体计数方式以所选套餐为准。 校园网可能更换公网来源 IP；直连家宽时，这可能被商家识别为新的来源。采用本方案时，家宽商家通常看到前置节点的公网 IP；切换节点或自动选路也可能改变这个来源。

如果商家按来源 IP 计数且旧连接尚未释放，即使只有两台电脑，也可能触发上限。购买前向客服确认计数、释放和白名单规则，结合自己的网络及设备数量自主决定是否购买。前置节点变化时，家宽需要的来源白名单也要相应核对。

来源：Mihomo 链式代理、Clash Verge 全局扩展脚本。

02 扩展脚本与实际验收（续）

下面是 SOCKS5 家宽的示例。让 Agent 按真实资料替换地址、端口、认证和前置节点名，再合并到已有脚本。完整文件见 链式代理脚本，详细步骤见 Agent 配置说明。

function main(config) {
  const name = "Claude-静态家宽";
  const exit = {
    name, type: "socks5",
    server: "替换为家宽地址", port: 1080,
    username: "替换为用户名", password: "替换为密码",
    "dialer-proxy": "替换为现有固定前置节点名"
  };
  config.proxies = (config.proxies || [])
    .filter(proxy => proxy.name !== name).concat(exit);
  const rules = ["anthropic.com", "claude.ai", "claude.com",
    "claudeusercontent.com", "claudemcpcontent.com"]
    .map(domain => `DOMAIN-SUFFIX,${domain},${name}`);
  config.rules = rules.concat((config.rules || [])
    .filter(rule => !rules.includes(rule)));
  return config;
}

前置节点须真实存在，且不能指向家宽节点本身或包含它的循环代理组。HTTP / HTTPS 家宽按商家协议修改，IP 白名单认证时去掉用户名和密码。端口 1080 只是示例。域名规则覆盖 Claude 的主要服务、登录与内容域名，其他网站沿用原规则；新增第三方服务按实际请求处理。

请 Agent 验证实际路径并交接

验证对象 需要拿到的结果
生成配置与规则 家宽节点正确引用前置；上述域名在宽泛规则前命中家宽
CLI 与登录浏览器 实际请求经过前置与家宽；CLI 发出一条简短请求成功
家宽出口 定向经家宽的 IP 查询结果与供应商资料吻合，记录时间
日常使用与恢复 本机 HTTP / mixed 端口、前置节点、家宽出口、CLI 启动方法、备份及 RUN.md 位置

普通查 IP 网页可能仍走原梯子，不能据此判断 Claude 的出口。让 Agent 结合真实目标连接链与定向查询取证。WSL、容器和 SSH 远端按实际运行位置验证。故障时按保存的方案恢复，保持校园认证和管理连接。

03 让 Claude Code CLI 使用代理

本地代理已启动，不代表 CLI 一定使用了它。 先让 Agent 确认真实的 HTTP / mixed 监听地址。下面的 7890 只是示例，执行前替换为交接卡中的实际端口。

先在当前终端接入

Windows PowerShell：

$env:HTTPS_PROXY = 'http://127.0.0.1:7890'
$env:HTTP_PROXY = $env:HTTPS_PROXY
claude

macOS / Linux：

export HTTPS_PROXY=http://127.0.0.1:7890
export HTTP_PROXY="$HTTPS_PROXY"
claude

这些变量作用于当前终端及它新启动的子进程。已经运行的 Claude Code 会话不会自动继承之后修改的终端变量；从配置好的终端启动新会话。

日常使用时，由 Agent 合并持久配置

独立运行的 CLI 可在用户级 ~/.claude/settings.json 的 env 中配置代理。下面是需要合并的片段，端口仍须换成实际值：

{
  "env": {
    "HTTPS_PROXY": "http://127.0.0.1:7890",
    "HTTP_PROXY": "http://127.0.0.1:7890"
  }
}

已有配置保留，由 Agent 合并 env。已有代理变量、NO_PROXY 或自定义网关时，让它核对生效顺序；小写代理变量可能优先于大写变量。Claude Code 需要 HTTP(S) 入口，不能仅填 SOCKS 地址。

最后在真实 CLI 中发一条简短请求确认可用，并由 Agent 核对连接路径。相关语义见 官方网络配置。

06 怎样让 Claude 把事情做完整

把目标、材料、范围、交付文件和完成标准说清楚。大任务先讨论方案，范围明确后让它执行；常规小任务可以直接交付。

修改代码

目标：修复我刚才提供的报错。
请先定位相关代码和触发条件，再做必要修改。
范围：围绕这次问题处理，遵循项目已有约定。
完成后说明改了什么，并运行能验证该问题的检查。

整理资料或撰写说明

请阅读当前目录下我指定的资料，整理成一份中文说明。
先说明资料覆盖什么，再按主题归纳要点。
输出到 notes/summary.md，保留可追溯的文件或页码信息。
无法读取或没有依据的内容，请列为待补充。

处理数据

请分析我指定的 CSV，先解释字段、单位和数据范围。
按我给出的目标完成计算，把结果与可复用脚本保存到 results/。
说明缺失数据、使用的假设，以及主要结论对应的计算。

收到结果后怎么继续

需要调整时直接说明具体差异，例如“保留现有结构，把第三段写得更具体”，或“报错仍在，复现步骤是……”。任务跑偏时打断并重述目标。工具报错时让它解释原因，再针对失败点继续。

10 故障处理、维护与账号使用边界

按提示分开处理

现象 先做什么
安装后找不到 claude 打开新终端，交给 Agent 检查安装结果与 PATH
浏览器能用，CLI 超时 查 HTTP(S) 代理、环境继承、执行位置和实际路径
CLI 提示未登录 查看 claude auth status --text，按官方流程重新登录
明确提示额度耗尽 查看 /usage 的窗口和恢复时间，安排继续任务
403、认证或连接错误 保存完整提示，分别检查认证、服务状态和网络
明确提示账号停用 按官方通知和申诉入口处理
代理退出后无法联网 按交接卡检查代理及断线保护，使用预先准备的恢复方法

平时保持已验证的线路和设置；按管理员资料登记续费。换设备、换网络或升级客户端后复查受影响的部分。手机、WSL、容器和远端的 Claude 分别验证。

网络配置与“防封”的边界

CLI 是日常工作方式，不提供免封能力。固定出口、实际请求验证和断线保护用于减少配置遗漏；第三方检测分数不能代表封号概率。个人账号按本人使用要求管理，多人使用采用各自账号或组织席位，服务地区和使用方式遵守平台规则。

指南与 GitHub 地址可以转发。节点二维码、订阅、密码和账号令牌只交给指定维护者，保留在私有位置。

官方入口：服务状态 · 账号申诉 · 账号条款 · 支持地区。

可选的 VPS 购买入口

确有自建其他服务的需求时，可参考 LightNode、Vultr 和 Akamai / Linode。价格与库存以商家页面为准。本文推荐的 Clash 链式代理使用已有梯子连接家宽。
