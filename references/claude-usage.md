# Claude 应用接入与故障分流

供目标应用为浏览器、Claude Code、Desktop 或 IDE 的任务按需读取。配置与检测仍执行 `SKILL.md` 的 B0–B6、D0–D3，本文件补充应用差异和具体故障的判断。

## 接入实际应用

先确定请求运行在本机、WSL、容器、SSH 远端还是手机。宿主机浏览器通过不能替代其他位置的应用验证。

- Claude Code 的代理设置按当前 [官方网络配置](https://code.claude.com/docs/en/network-config) 和实际进程继承核对。需要 HTTP(S) 入口时使用客户端提供的 HTTP / mixed 监听，不能仅设置 SOCKS 地址后宣布已接入。
- 检查系统代理、应用设置、大小写 HTTP(S) 变量及 `NO_PROXY` 的实际作用。已有连接或控制器能解释路径时，先利用已有证据。
- 浏览器使用真实用户配置核对出口和所需环境字段。原生客户端、登录页及流式请求按各自路径验证；Desktop 和 IDE 不直接套用 CLI 的结论。
- iPhone 节点与规则配置分别处理，在实际使用的 Wi-Fi / 蜂窝路径验收。电脑上的防火墙策略不随二维码转移到手机。
- 中转机分开验证管理、转发和机上应用；有真实下游时从下游取证。

## 第三方检测与隐私设置

[Fuck Claude](https://github.com/LinXiaoTao/FuckClaude) 提供浏览器环境和网络线索。提取具体信号交给 detection.md 核对，不把分数或“中国用户”标签当作 Anthropic 的封禁规则。

优先处理实测出口偏差、应用未接入和预期外的公网连接。时区、语言、字体、DNS 地址或私网 ICE 不能单独证明公网旁路；保留用户需要的输入法、界面和工作软件。旧版本逆向分析中的日期 / Unicode 行为不能替代当前进程证据。

用户主动要求调整可选遥测时，先查当前 [官方数据使用说明](https://code.claude.com/docs/en/data-usage)，说明影响并合并相关设置；保留原配置，不覆盖整份 `settings.json`。隐私开关不作为网络验收的必选项。

## 按报错选择处理路线

| 现象 | 下一步 |
|---|---|
| 源配置正确，实际出口变化 | 优先检查 Clash Verge 的全局 `profiles/Script.js`、自有出口识别、生成配置和实际代理组。出现 `__RELAY_TRANSIT_*` 等重写时先定位来源，避免重复导入或先改服务器 |
| 网页正常，Claude Code 失败 | 查实际执行位置、HTTP(S) 代理、变量优先级、`NO_PROXY`、认证及目标接口 |
| 电脑可用，手机不可用 | 对照手机入口、是否依赖中转、规则及真实连接，不先重建服务器 |
| 同一线路在多设备均超时 | 查账单 / 流量、实例、服务和路径。结合测量范围定位共同故障点 |
| 明确提示额度耗尽或 429 | 读取完整用量提示与重置时间；按提示区分额度与其他限流，不以更换 IP 处理账号额度 |
| 403、登录失败或连接错误 | 查看完整提示、[官方服务状态](https://status.claude.com/) 和认证情况，分别排查应用与网络 |
| 明确显示 suspended / disabled | 按 [官方申诉说明](https://support.claude.com/en/articles/8241253-safeguards-warnings-and-appeals) 保留资料并交用户处理；未经要求不代发邮件或工单 |
| 代理退出后无法访问网络 | 先核对客户端和现有断线保护，按已保存的恢复动作处理，不把撤销保护当作默认修复 |

失败必须记录原因和已知范围。修改后复测受影响项目，已有充分证据不重复测量。

## 适用范围

tanuki 交付配置、实际连接证据和恢复方式。网络检测不能推算封号概率或保证账号安全；账号和服务地区资格按平台当前规则处理。检测与修复仅覆盖用户授权的设备、应用和资源。
