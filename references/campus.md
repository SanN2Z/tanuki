# 校园网、加密接入与管理路径

先按 roles.md 确认设备用途。本文件用于配置 B1/B3/B4，或检测 D1/D2 的只读取证。检测模式不执行其中的配置、持久化、切换或故障演练。校园认证、第一跳、DNS、TUN 和管理连接按实际个人/转发路径处理。

## 先确认当前网络

读取正在使用的有线/Wi-Fi 接口、DHCP 网关、DNS、校园认证状态和实际访问失败。门户未认证先让用户正常认证。已知必须保留的校园网段、门户域名、实验室主机、frp 服务器和远程桌面端点由当前配置及用户授权范围确定，不扫描整个校园网。

Windows 使用 Get-NetIPConfiguration / route print；macOS 使用 route -n get、scutil --dns 与 networksetup；Linux 使用 ip route、resolvectl。动态 DHCP 网关必须取当前值。

先按“解析 → TCP → 协议握手 → HTTPS → 应用”的顺序缩小问题。UDP DNS 被限不代表 TCP DNS 或 DoH 也不可用；TCP 连接成功也不代表代理握手成功。

## 第一跳协议与最终出口

VPS 起步方案使用 VLESS + REALITY + Vision over TCP；客户端 TLS 配置与服务端实际匹配。若目标校园路径只允许某个可用端口，基于真实端口测试和服务器权限选择端口，不靠把名称改成“校园/日本”解决。

REALITY 的握手目标用于传输协议，不能改变最终 IP 的国家或 ASN。不要把协议配置成功表述为校园网络看不见连接。第一跳与目标站点 TLS 分开验证；不默认加入 MAC、TTL 修改、校园账号冒用或未知分片参数。

已有 TLS VPN/代理可用时直接复用。校园 UDP 不可用时优先检验可用的 TCP 传输路径；若必须改协议或服务器，先在独立配置验证，不打断唯一管理入口。

## 管理路径先于 TUN

画清两条链：

~~~text
管理：远程管理端 → 现有 frp / VPN / SSH → 目标电脑 → 所需内网
业务：目标应用 → 本机代理/TUN → [中转] → JP 最终出口
~~~

1. 取 frpc 实际 serverAddr、SSH 对端、远程桌面所需域名/进程、代理底层端点和要用的内网网段。只读取必要字段并脱敏。
2. 查每个地址的实际 OS 路由。需要保留的管理连接在代理停止或出口故障时仍应有明确路径。
3. TUN 的 route-exclude-address 与代理规则里的 DIRECT 分别配置：前者决定哪些地址不进入代理；后者只影响已经进入内核的连接。
4. 仅对本机确需的地址/网段生成排除和持久路由；不照搬作者的 10/8、校园 DNS、en0 或 utun 名称。其他 VPN、容器网络的重叠网段应按实际路由处理。
5. 代理底层连接要避免递归进入自身 TUN；用内核支持的自动接口选择、明确出站接口或所需主机路由处理并实测。自动选择成功就不再堆额外路由。
6. 在授权的切换前准备独立入口或本地操作者、原配置和回退命令。切换后先验证管理连接、内网、门户，再验证 JP 路径。

桌面通过客户端支持的配置扩展持久化，网关通过已采用的系统服务/网络配置持久化。不要只 PATCH 运行状态后宣布完成。DHCP 环境不要固化旧网关；只有需要长期远程管理的网关才配置随网络变化维护路由的机制。

frp 或远程桌面已经能工作时保留它。裸机普通用户不必为了技能安装 frp、远程桌面、额外跳板或健康检查守护进程。

## DNS 分成三类

| 用途 | 路径 | 验收 |
|---|---|---|
| 代理端点 bootstrap | 当前网络可达的解析器，避免依赖尚未建立的隧道 | 端点能解析并真正完成握手 |
| 校园内网/门户及明确直连业务 | 实测可用的本地/校园解析器或指定直连上游 | 该业务在 JP 出口不可用时仍满足约定 |
| 需要 JP 路径的应用 | 经本次出口的解析器/DoH | 实际 DNS 上游与 HTTPS 连接都通过 |

Mihomo 调整按当前 [DNS 文档](https://wiki.metacubex.one/en/config/dns/)：

- 根据上述三类设置 proxy-server-nameserver、nameserver / nameserver-policy 与 direct-nameserver。
- 使用 respect-rules 时注意上游本身匹配哪条规则；需直连的上游可明确选择 DIRECT，应用 DoH 可明确选择 JP 组。
- 配置 direct-nameserver 后，需要遵循 nameserver-policy 的直连业务同步检查 direct-nameserver-follow-policy。
- 修改 GUI 的 DNS 专用覆盖文件时确认它要的是内部字段还是完整 dns: 对象；最终运行 YAML 只能有正确层级，不能变成 dns: {dns: ...}。
- 开启 DNS hijack 前确认 DNS 服务真的启用并监听。IPv4/IPv6、UDP/TCP 查询与应用内 DoH 按实际使用范围分别验收。
- fake-IP 答案证明的是本地映射，不能代替出口和上游 DNS 验收。禁止将测试保留网段 198.18.0.0/15 报成公网泄漏。

校园 DNS 不能解析某个公共业务时，针对该业务测另一个可达上游；不把所有内网域名交给公网 DNS，也不因地址位于国内就全局禁用。

## 规则、运行配置与退出行为

规则按真实优先级编排：必要管理/校园例外、受保护目标的代理规则、经用户确定的其他例外、最终 MATCH 到所选出口。受保护目标不得被宽泛 DIRECT 规则提前截获；规则位于 MATCH 后不会生效。

进程名按 OS 的实际可执行文件确定；macOS 不照抄 Windows .exe。UU/其他远程桌面有多进程时，结合新鲜连接记录确定需覆盖的部分。不用全局 UDP REJECT 破坏需要直连的远程控制；只处理已确认的问题路径。

检查 GUI 设置、订阅源、全局脚本、配置扩展、生成 YAML、controller 和 OS 路由。客户端配置层的数组合并语义按所用版本确认，避免整段替换丢掉已有例外。

故障分开记录：

- 出口下线但代理仍运行：目标业务应失败或切至用户认可的备用最终出口。
- 本地代理进程退出：TUN 规则本身不能保证 OS 不恢复直连；需要这一保护时另行准备 OS 级方案并安排有恢复通道的验收。
- 校园认证过期、DHCP 更新、换网络：影响的是基础连接或路由，不能用换账号/改地区解决。

未做断线/重启测试的项目标未验证，不因为代理组没有 DIRECT 就称具备 OS 级断网保护。
