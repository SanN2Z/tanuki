# 验收、回退与交接

验收围绕已确认的用途和模式进行。配置/修复采用下述顺序；仅检测按 detection.md 报告已有证据，不因验收而部署、切换或演练。个人应用、中转转发和机上应用分别标注位置。已有证据能回答的问题不重复测；修复改变了哪个层，就复测该层与必要的关联连接。

## 验收顺序

1. **配置与部署**：实际版本能解析配置，必填值齐全；服务端存在且运行，本地只起预期实例。只在有新服务的分支检查服务端。
2. **目标电脑隔离试连**：真正的协议握手、HTTPS、两家出口观测和所需 DNS 通过；显示实际连接链，说明是否仍经过旧 TUN。
3. **当前管理与校园路径**：本机能继续管理，必要远程连接与内网可用。没有该依赖时不增加虚构测试。
4. **实际应用与下游**：个人电脑记录实际浏览器、Claude CLI、IDE/Desktop 的连接；中转机从下游真实接入方式验证转发链，并单独验证机上实际应用。核对目标域名和登录/流式连接。下游不可访问时保持未验证，不能用中转机自己的 curl 代替。
5. **地区与语言**：仅在运行目标应用的设备/进程核对时区 ID、偏移、地区格式、浏览器语言/请求头与 Intl；纯转发机该项不适用。UI 和输入法按用户目标保留。
6. **泄漏与路由范围**：DNS、IPv4/IPv6、应用 DoH、UDP/QUIC、WebRTC 按 surfaces.md 解释。不通、无候选或没有工具不是“已通过”。
7. **持久化与故障**：先读取持久配置。获得相应维护窗口时再验证重载/重启/出口失效/客户端退出；只在实际有中转或备用出口时测这些分支。隔离故障测试不能冒充 OS 全局断网保护。

用户要全系统覆盖时，只有浏览器/CLI HTTP 通过不够。保留 IPv6、UDP 和无法观察的应用为待验证项，直到有相应实际证据。有限范围已通过可以说明“已覆盖这些应用”，不能扩写成整机完成。

## 正常与故障预期

| 场景 | 预期 |
|---|---|
| 所选 JP 出口可用 | 实际应用走该出口，TLS 正常，所需 DNS 能解析 |
| 仅中转不可用 | 用户认可的备用链路仍指向相同类别的最终出口，或连接失败 |
| 所有认可的最终出口不可用，代理仍运行 | 目标业务失败，无校园公网/无关供应商兜底 |
| 必要校园/管理业务 | 按约定独立于 JP 出口，保留认证和管理能力 |
| 客户端退出 / TUN 消失 | 取决于 OS 级策略；没有测试时明确未验证 |

只对本次资源运行，不能断开其他人的出口。频繁切换、节点压测或长时间后台监控不属于默认验收。

## 回退

执行 B4 前，把“备份路径 + 恢复动作 + 哪个进程需要重载”写进 RUN.md。恢复只针对本次改动。

- 代理失败：恢复原配置/活动选择、原系统代理或 TUN 状态，验证管理与基础网络。新测试进程只按记录的 PID 结束。
- 路由/DNS 失败：恢复所改接口的原 DHCP/DNS/路由设置；保留别的 VPN 与无关规则。
- 地区/语言问题：恢复记录的原值，保留用户既有语言和输入法，重启必要进程后验证。
- 新 VPS 服务失败：按 network-setup.md 停用本次服务、撤销本次新规则，保留 SSH。已有共享服务只恢复本次配置片段。
- 切换承载唯一远程会话：现场操作者执行预先保存的恢复命令；没有现场或备用入口时，应停在切换前。

恢复成功与目标完成分开记录。既有网络恢复了，但 JP 配置尚未通过时，状态仍是待解决。

## 交付结果

先给已实际达到的结果，然后按需要给一张简表：

| 项目 | 状态 | 实际证据 | 改动与回退 |
|---|---|---|---|
| 最终出口/应用 | 一致、已修复或未验证 | 当前设备、时间、查询/连接链 | 配置路径、备份与恢复动作 |
| 系统/浏览器 | 一致、已修复或待重启 | 原值、现值与实际进程结果 | 修改项 |
| 待用户项 | 待用户 | 缺少的资源或交互 | 操作与续接命令 |

按角色写覆盖说明：个人电脑为实际应用环境；中转机为管理链、下游转发及实际存在的机上应用。未完成部分集中写在“未验证与待办”。不按语言、字体、硬件或单个 IP 库打国籍分数。

给使用者保留 RUN.md、私有配置位置、回退命令和复查入口；续费、白名单变化、换网络、客户端升级发生后，只复查受影响路径。默认不注册定时任务或自动发送消息。

分发技能只打包 SKILL.md、agents/、references/、assets/、scripts/ 和源码测试。排除 RUN.md、真实观测、私有节点、订阅、证书/密钥、客户端导出、下载的可执行文件和备份。其他人得到的是可独立执行的流程，不是原作者的账号资源。
