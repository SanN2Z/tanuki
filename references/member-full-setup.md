# 成员完整配置 SOP

用于「家宽截图 / 代理信息 + 让本机 Codex 配好环境」的请求。执行范围是个人电脑的环境准备、Clash 链式代理、Claude Code、登录浏览器、防火墙与防泄漏验证。已有配置先检测修复，缺少的部分从零准备。沿用入口中已有的用途、资源和授权，完成一个阶段后继续下一阶段。

## 1. 接收家宽信息

支持供应商截图、分字段文本，以及 `主机:端口:用户名:密码` 形式的完整代理。直接读取用户已发的资料，不要求再抄一遍。图片无法辨认某个必填值时，只补充该值。文本中的密码可能含冒号，前三个分隔符之后保留为完整密码；私有文件使用 JSON/YAML 序列化填写。

| 供应商显示 | 本次使用 |
|---|---|
| 中转代理详情的主机、端口、用户名、密码 | 一套完整的供应商接入端点与认证信息 |
| 完整代理 | 与详情交叉核对，不能混用另一端点的端口或密码 |
| 原始代理 | 供应商给出的另一种接入方式，作为备选资料保存 |
| 出口 IP 详情 | 最终家宽出口的预期 IP，用于验收，不能直接当成代理入口 |
| 地区 | 本次目标国家，覆盖常规入口的日本默认值 |
| 协议、到期、设备限制 | 按实际说明记录；截图未提供的保留待补充 |

「中转代理」是供应商的端点名称，与组员已有梯子承担的前置角色分开记录。链路为：本机应用 → 本机 Clash → 组员现有梯子前置 → 供应商接入端点 → 分配的家宽出口 → 目标服务。

同端点明确支持 HTTP、HTTPS 和 SOCKS5 时，可先按 SOCKS5/TCP 接入 Mihomo；具体端口与 TLS 能力按供应商说明验证。CLI 接入本机 HTTP / mixed 监听。

把完整资料保存到 `<work-dir>/residential.private.json`，本地权限限本用户，报告只记录地区、端点和认证已设置。截图、凭据、订阅与私有文件留在成员机器，公开技能包使用占位示例。

## 2. 盘点环境并准备恢复

按 [平台操作](platforms.md) 和 [校园网与管理路径](campus.md) 只读获取：系统与权限、实际执行位置、Clash/Mihomo 版本、当前订阅、代理组选择、全局及订阅级脚本、最终配置、监听、TUN、路由、DNS、浏览器与 CLI，以及现有防火墙策略。读取实际必要片段，凭据不打印到日志。

从当前连接与选择中复用可用前置节点，优先固定节点。节点明确且可用时直接采用；只有多条用途不同且无法判断时才让用户选择。保留校园门户、内网、SSH/远程桌面和执行配置的 Codex 连接。

新建或读取私有 `RUN.md`，登记目标国家、家宽入口与预期出口、前置、保护的应用、当前阶段、备份和恢复命令。修改前保存将改动的脚本、浏览器设置、应用代理与防火墙规则原件。必要的客户端缺失时按官方发行版准备；系统密码、网络扩展授权和账号登录交用户在原界面完成。

## 3. 生成并验证 Clash 链式代理

按 [链式代理流程](clash-chain.md) 和 [脚本模板](../assets/clash-verge-claude-chain.js) 合并全局扩展脚本。家宽节点的 `dialer-proxy` 指向实际前置，Claude / Anthropic 域名规则在原宽泛规则之前，其他网站保留原规则。已有脚本只保留一个 `main` 入口，检查后续订阅级扩展是否覆盖了结果。

先用实际 Mihomo 内核离线解析候选配置，再用独立目录、空闲回环端口、关闭 TUN 的测试实例验证协议、定向家宽查询及实际目标请求。比对分配的出口 IP 和国家，国家不同或 IP 不符时查供应商资源与连接链，不通过修改系统地区消除差异。家宽策略只包含分配的最终出口；前置和 DIRECT 不作为家宽失败的自动替代。

保存到客户端支持的持久配置层，在本次授权内应用并核对最终生成配置、规则模式和新连接链。保持运行中的 Clash Verge / Mihomo，不通过停止或重启它们加载配置。订阅更新和切换后仍须保持家宽节点及有效前置。

## 4. 配置 CLI 与真实浏览器

按 [Claude 接入](claude-usage.md) 核对 Claude Code 的有效代理、认证和实际运行位置，缺少时安装官方客户端。合并本机 HTTP(S) 代理到用户级配置或所用启动环境；保留其他设置和账号。已有登录能用就复用，需要登录时交用户走官方流程。

浏览器使用成员平常使用的真实配置，按实际系统代理 / TUN / 浏览器设置连接本机 Clash，确认 Claude 页面、登录跳转与流式连接都走家宽。保留书签、已有登录和必要输入法。浏览器 DoH、站点定位权限、WebRTC 公网候选与 UDP/QUIC 逐项按 [检测面](surfaces.md) 取证，修复实际旁路；网络隐私设置的原值写入恢复记录。

采用用户分配的目标国家。日本资源可按已授权的日本地区目标处理；美国等多时区地区，仅有国家和 IP 时不推断城市时区。需要调整时先确认具体目标时区，保留中文界面、字体和输入法。采集器通过 `--target-country <国家代码>` 传入目标；明确需要核对时区时再传 `--target-timezone <本机系统使用的时区 ID>`。

## 5. 配置防火墙与防泄漏

在已有保护的基础上限制本次受保护应用的直接公网出站，保留其到本机代理的通道、代理内核连接前置的通道，以及已确认的校园与管理连接。根据平台和实际程序路径选择规则，展示将应用的变更与恢复命令，在本次明确授权内执行。常规应用规则不影响无关程序；macOS 整机断线保护单独按下述条件处理。

- **Windows**：检查有效策略、程序完整路径、物理与虚拟接口、IPv4/IPv6 和共享运行时。使用作用范围明确且互不冲突的规则；显式 Block 优先于冲突的 Allow，不能用「全出站 Block + 本地代理 Allow」假定能得到例外。保留系统和 Agent 沙箱规则。
- **macOS**：优先复用现有出站过滤方案。使用 Clash Verge Rev / Mihomo 服务模式且已开启 TUN 时，可按 [Valdemar-Yu/killswitch 原仓库](https://github.com/Valdemar-Yu/killswitch) 接入整机断线保护。读取上游当前安装说明，核对核心路径、用户、Unix API、权限及已有 PF 策略；确认现场或独立恢复入口，并保存 `killswitch rollback` 后再启用。上游安装会重载 PF 并清理连接状态，唯一远程入口不具备恢复条件时先交付待接入方案。其他 PF 方案沿用独立 anchor 和本次作用范围。系统自带入站防火墙不等同于出站保护。
- **Linux**：沿用本机的 nftables / 防火墙工具，为本次保护添加独立命名的规则，核对应用身份、接口、回环、IPv4/IPv6 和规则优先级，保留既有管理规则。

按实际需要配置 Mihomo DNS、TUN 和路由覆盖，分别验证代理端点解析、目标业务解析、应用 DoH、IPv4/IPv6 及需要的 UDP。校园门户与内网使用其已验证路径。发现 WebRTC 或 QUIC 旁路时调整相关应用策略或覆盖范围，并验证通话、管理等必要功能。

防火墙规则绑定实际应用及范围；共享 Node / 终端需核对受影响程序，程序升级后复核路径。维护权限只用于本次配置，交付恢复命令，不新增长期维护豁免。家宽失效、前置失效和本机代理退出是不同的失败条件，分别处理。

## 6. 验收并交接

按 [验收流程](acceptance.md) 完成受影响路径的检查：

1. 真实 Claude CLI 请求成功，登录浏览器的关键请求命中家宽；家宽定向查询与分配的 IP / 国家吻合，普通网站仍按原规则。
2. DNS、IPv4/IPv6、浏览器 DoH、WebRTC 和必要 UDP 的实际证据符合目标；校园认证、内网与管理连接保持可用。
3. 防火墙有效规则覆盖实际程序和接口，应用经代理可用，受保护路径绕过代理的尝试被拒绝；在隔离候选中验证家宽 / 前置失效时失败。
4. 代理退出场景采用不会破坏当前管理连接的独立测试路径；只清理本次创建并记录 PID 的测试进程，保留工作中的代理。保存持久配置和恢复动作。

向成员交付 `START-HERE.md`：日常启动顺序、本机端口、前置与家宽出口、Claude 会话 / 用量命令、恢复方法、续费资料、`RUN.md` 位置。接入 killswitch 的 Mac 另附上游链接、实际状态与离线回滚入口。报告写明本次完成的保护范围，集中列出未验证项与需要本人完成的一步。

## 限制

「一键」指组员发出一次配置请求后，由 Agent 连续完成上述 SOP。系统授权、付款、验证码与账号登录仍需本人操作。缺少出站过滤能力或系统权限时，保留已完成的配置和对应人工动作；无法实际测试的断线、重启或客户端退出场景保持未验证。隔离故障测试不能代替当前整机的退出测试，配置检测也不能保证平台账号不受限制。

killswitch 是可选的 macOS 整机保护：检测内核与 TUN 失效后封锁普通外网，健康时保留原分流；它不检测家宽节点可用性，也不替代目标域名分流或应用直连限制。其检测存在轮询间隔，接入和故障状态可能影响其他 VPN、校园认证与远程连接，须按上游说明验证兼容和恢复。Windows / Linux 继续采用各自平台方案。

官方依据：[Windows 防火墙规则优先级](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules)、[Apple 防火墙](https://support.apple.com/guide/security/firewall-security-in-macos-seca0e83763f/1/web/1)、[Mihomo TUN](https://wiki.metacubex.one/config/inbound/tun/)。
